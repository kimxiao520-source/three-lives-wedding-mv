# 02 定片型

## 1. 输入与停点

输入是本轮创作范围、用户的观看意图、已有故事及必须保留的限制。世数、年代和时长已定则沿用，未定且属于本轮设计范围则作为候选提出。

连作品要表达浪漫相处还是持续事件都无法从资料判断，且用户未授权提出方向时，停下确认观看意图。用户已选片型与现有故事相冲突时，列出具体冲突，不擅自改换片型。照片、音乐文件和生成工具不是本步必需输入。

## 2. 判断与执行

| 判断条件 | 片型与处理 |
| --- | --- |
| 重点是不同年代的相处、肖像、衣装与环境，事件之间不需要因果才能理解 | 以抒情多世 MV 组织；允许安静状态，不强加阻隔或相认 |
| 一个尚未完成的关系目标跨世推进，下一段受上一段的选择影响 | 以连续世界故事组织；写明每次换世后目标、困难或选择怎样变化 |
| 只有一段有小事件，其余是抒情相处 | 保留主要片型，把小事件当局部段落，不为它重建全片世界规则 |

先写一句观众能持续关注的内容。抒情例：“看两人在明代庭院、民国照相馆与现代街头怎样显露不同默契。”只有剧情确实有待完成的事，才写“分持的玉佩最终怎样合拢”这类问题。

去掉年代标签再读各段：若只剩同样的对视和牵手，需补相处内容的区别；不能靠世数或衣装套数冒充结构。给出一个主方案及理由，真实存在方向分歧时再给备选。本公开版仅设计日常行为与关系接触，不展开奇幻大动作；回忆或穿越机制只在作品已选时使用。

## 3. 交付格式

| 字段 | 填写要求 |
| --- | --- |
| 主要片型 | 二者选一，混用时说明局部范围 |
| 整片观看线 | 一句可由实际画面兑现的话 |
| 选择理由 | 对应用户意图或已有内容，不写笼统评价 |
| 各世贡献 | 每世分别提供哪一种相处内容或目标变化 |
| 结尾兑现 | 两人的什么状态完成观看期待 |
| 已定与候选 | 明确哪些沿用、哪些是本轮建议 |

## 4. 交付前自检

1. 片型与实际内容对应；抒情片被硬加冲突时退回重选组织法。
2. 观看线可由画面兑现，没有依赖说明文字的空目标；否则重写观看线。
3. 各世有内容差异，连续故事的目标变化可列明；只换造型则退回内容设计。
4. 结尾回应前面建立的期待，没有自行追加现实框架或奇幻动作；越界则删改。

未通过就修正本步结论，不带着互相冲突的片型继续设计。
