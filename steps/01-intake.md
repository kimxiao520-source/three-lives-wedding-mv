# 01 接手

目标：识别用户要什么成果，恢复已有选择，直接进入能开展的创作。需求卡由你从上下文整理，不要求用户先填表。

先判断用户是在起新作、续做、修局部，还是询问已有内容。问答直接回答；创作请求先找到对应阶段及其输入，不把“写一段剧本”扩大成全套素材收集。

制作真实新人形象时，读取已有正脸、侧脸及全身照片，记录可确认的身高差。只在当前出图确实缺少身份信息时索取相应照片；纯文字设计不因缺照片停工，也不用陌生脸替代新人。

按当前任务需要从下表提取信息。区分用户已定、你提出的创作候选和真正待补项；虚构故事可创作，不冒称新人的真实经历。

| 项目 | 填写内容 |
| --- | --- |
| 新人 | 两人的称呼、照片对应关系、身高差 |
| 故事年代 | 想呈现几世，分别在哪个年代；尚未选择的年代 |
| 制作方式 | 全部 AI、部分实拍；已有实拍素材用于哪些段落 |
| 放映要求 | 完整影片目标时长、画面比例、播放场合 |
| 音乐与人声 | 曲目或音频是否已提供；是否需要对白、旁白或纯音乐 |
| 结尾 | 是否落在现代婚礼；希望两人最终呈现什么关系状态 |
| 执行能力 | 自行检查环境能否读图、生图、编辑图、多图生成视频及剪辑；仅在实际执行需要时核对 |
| 已定内容 | 人物、年代、故事、服装、场景及已选图片和视频 |
| 本轮任务 | 从哪里接着做；哪些内容明确保留；待补资料 |

年代与制作方式分开判断：现代婚礼可以由 AI 制作，古代段也可能包含实拍。不要由服装或地点推断制作方式。

对只说“做一个多世婚礼 MV”的用户，先提出一条具体观看线与各世内容候选，简短说明关键假设，再询问确实影响方向的选择；不要先追问工具、型号、全部照片和音乐。时长未定可提出适合候选内容的长度，不能冒称用户已确认。

工具由执行者适配。用户已经指定工具时沿用；环境可调用时自行核对输入能力；只能写词时直接交完整词与素材要求。只有实际操作被账户访问或入口能力阻挡时，才询问对应问题，不让工具缺失阻止故事、表演或镜头设计。

用简短接手摘要说明已定内容、本轮起点及必要缺项，然后继续交付本轮成果；仅在用户要求需求梳理时单独交完整需求卡。已有可用内容不因重新接手而重做。
